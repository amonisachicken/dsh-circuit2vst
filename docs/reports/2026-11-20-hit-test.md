# dsh-circuit2vst 电路设计器「复制/移动时点不中目标器件」— 反馈

## 概要

在电路设计器里用 **复制模式（`d`）或移动模式（`m`）** 点选器件时，点击的是眼前这个器件，实际命中的却是**另一个更早创建的器件**；而且**进入模式后的第一次点击经常被吞掉**，要点第二次才生效。

排查后确认这是两个独立缺陷，都能稳定复现：

| # | 缺陷 | 触发条件 |
|---|---|---|
| A | 命中判定按 **文档数组顺序** 决胜，与 **绘制层级（z-order）** 相反 | 两个器件的命中框有重叠（电阻相距 < 15 mm 即可），重叠区域内永远选最先创建的那个 |
| B | 双击判定跨越模式切换，**吞掉模式首击** | 在视图模式点选某器件后 **400 ms 内**按 `d`/`m` 再点同一器件 |

其中 **A 直接对应“点的是这个、命中的是之前创建的另一个”**，**B 直接对应“第一次点不动、第二次才行”**。

## 环境

| 项 | 值 |
|---|---|
| dsh-circuit2vst | `0.1.8`，commit `8d150011883eea1b251e48643ae07495c360b00c` |
| DeepSeek Harness | `0.2.2-rc.1`（web profile） |
| 系统 | CachyOS Linux / Chromium 内核 GUI |

## 复现 A：重叠区域总是命中更早创建的器件

### 步骤

1. 电路里放两个器件，中心相距 ≤ 一个网格以上（例如两个电阻相距 2.5 mm，或复制后副本和原件位置重合）。
2. 按 `d` 进入复制模式。
3. 点击**后创建**（画在上层）的那个器件的中心。

### 实际

复制源是**先创建**的那个：

```
点击上层 TP9 -> 复制 TP1：点击落点（ctrl+r 旋转，esc 退出）
点击上层 R8  -> 复制 R1（10k）：点击落点（ctrl+r 旋转，esc 退出）
```

`R8`、`TP9` 是后加进去、视觉上压在上层的器件，但命中的是 `R1`、`TP1`。移动模式同样如此（两者共用同一个 `circuitHitTest`）。

### 根因

命中判定遍历 `doc.parts`，用**严格小于**保留第一个最小距离：

```js
// src/client/circuit-canvas.js:191  circuitHitTest
for (const part of doc.parts) {
  ...
  const distance = Math.min(boxDistance, pinDistance)
  if (distance <= HIT_TOLERANCE_MM && (bestPart === null || distance < bestPart.distance)) {
    bestPart = { id: part.id, distance }     // ← 同距离时保留先遍历到的（更早创建）
  }
}
```

而绘制是**按同一数组顺序**，后创建的画在上层：

```js
// src/client/circuit-canvas.js:1736
node('g', null, doc.parts.map((part) => { ... }))
```

所以命中优先级与视觉层级正好相反。

关键在于**距离 0 的区域很大**：命中框不是符号外框，而是内缩 25% 的“内框”，点到内框里距离就是 0：

```js
const insetX = (box.maxX - box.minX) * 0.25
const inner = { minX: box.minX + insetX, maxX: box.maxX - insetX, ... }
const boxDistance = Math.hypot(
  Math.max(inner.minX - at.x, 0, at.x - inner.maxX),
  Math.max(inner.minY - at.y, 0, at.y - inner.maxY),
)   // 内框内恒为 0
```

实测量级（`vendor/circuit/symbols.json`）：

| 符号 | 画布 | 内框 |
|---|---|---|
| resistor | 30 × 10 mm | **15 × 5 mm** |
| capacitor | 30 × 15 mm | 15 × 7.5 mm |
| test-point | 15 × 15 mm | 7.5 × 7.5 mm |

即：两个电阻的中心只要相距 **< 15 mm**，它们的“距离 0 区”就重叠；点在重叠区里两者距离都是 0，于是 `distance < best.distance` 不成立，**永远保留了数组里更早的那个**。电阻默认摆放间距本来就常在这个范围内。

### 建议修复

按“上层优先”决胜：反向遍历（后创建的先比较），保持严格小于即可：

```diff
-  for (const part of doc.parts) {
+  for (let index = doc.parts.length - 1; index >= 0; index -= 1) {
+    const part = doc.parts[index]
```

或者把比较改为 `distance <= bestPart.distance`（后遍历到的覆盖前者），效果等价但语义不如反向遍历直观。

补充建议：

- 命中排序更稳妥的做法是 `(distance, zIndex)` 二元组：距离优先，距离相同时取 `zIndex` 更大者（即数组下标更大者）。
- 导线优先规则（`bestWire.distance <= bestPart.distance + 1`）保持不变即可，目前只影响“点导线还是点器件”，与本次问题无关。

## 复现 B：模式首击被双击判定吞掉

### 步骤

1. 视图模式下单击器件 `TP1`（选中它）。
2. **400 ms 内**按 `d`（或 `m`）。
3. 立刻再单击同一个 `TP1`。

### 实际

第一次点击完全不生效，状态行没有任何变化，也没有进入放置/拿起：

```
1 视图模式点选 TP1 -> 状态: 5.5 px/mm
2 按下 d            -> 复制：点要复制的元件
3 第一次点 TP1      -> 复制：点要复制的元件      ← 没进入复制，模式首击被吞
4 第二次点 TP1      -> 复制 TP1（10k）：点击落点  ← 第二次才生效
```

移动模式同理（第一次点击不会拿起器件）；放置模式下也会吞掉落点（副本不会被放下）。

### 根因

`onPointerDown` 里双击判定放在最前面，且**不区分当前模式**：

```js
// src/client/circuit-canvas.js:1209-1231
const now = performance.now()
if (hit.partId !== null && lastClickRef.current.id === hit.partId && now - lastClickRef.current.at < 400) {
  lastClickRef.current = { id: null, at: 0 }
  ...
  setSelection(hit)
  return                      // ← 直接返回，后面的 d/m/place 分支永远不执行
}
lastClickRef.current = { id: hit.partId, at: now }
```

`lastClickRef` 在**每次 `pointerdown`** 都会被写入（第 1231 行，`onPointerUp` 只负责设置选中，不写它），而按 `d` / `m` 进入模式时**不会清空**：

```js
// src/client/circuit-canvas.js:993-994
case 'm': moveArmedRef.current = true; setMode({ kind: 'view' }); ...; return
case 'd': setMode({ kind: 'copy' }); ...; return
```

于是“先选中 → 按键 → 再点同一器件”这个最自然的操作序列，只要两步点击间隔 < 400 ms 就会被判成双击，模式点击被静默丢弃；由于 `lastClickRef` 在双击分支里被重置，**第二次点击就正常了**——这正是“第一次点不中、第二次才行”。

### 建议修复

任选其一（建议同时做前两条）：

1. **进入任何编辑模式时清空双击状态**：

   ```diff
    case 'd': setMode({ kind: 'copy' }); lastClickRef.current = { id: null, at: 0 }; ...
   ```

   `m`、`w`、`q`、`r/c/g`（放置）同理；`setMode` 里统一清空更省事。

2. **双击判定只在视图模式下生效**：把该分支包进 `if (current.kind === 'view' && !moveArmedRef.current && !dragRef.current) { ... }`，编辑模式优先处理。

3. 双击打开的属性/示波器判定本身可以保留，但应先让 `place`/`wire`/`delete`/`copy`/`move` 的分支执行完，再考虑双击语义（比如双击只在未消费点击时生效）。

## 复现方法说明（便于开发者复跑）

因为这是纯前端交互，我把 `src/client/circuit-canvas.js` 从安装包里取出，配上一份最小 React（`useState/useRef/useEffect/useCallback/useReducer/createElement`）和从 `client.js` 抽出的 `CIRCUIT_SYMBOLS` / `CIRCUIT_ART` / `CIRCUIT_EXAMPLES`，在 Node 里直接驱动组件、按绘制坐标派发 `pointerdown`：

- 点击坐标取自渲染出的 `<g transform="translate(x y) scale(s) …">`，与浏览器屏幕坐标一致；
- 结果通过状态行文本断言（`复制 <ref>：` / `移动：点击画布放下`）。

两个缺陷在这个最小环境里都能稳定复现，多次运行结果一致。

## 临时规避（用户侧）

- 尽量让两个器件的中心相距 **> 15 mm**，避免命中内框重叠；
- “先点选器件再按 `d`/`m`”时，**停顿 0.4 秒以上**再点第二次，可绕开双击吞击；
- 已经重叠的器件，用属性面板改坐标把它们分开，或删掉多余的副本。

## 影响

- 复制/移动会操作到错误器件，属于**数据修改类**误操作：可能移动了不该动的器件、或复制了错误的源，且不易察觉（两个器件外形一样）；
- 对重叠布局（原位复制、紧凑布线）几乎必然发生，属于高频路径。
